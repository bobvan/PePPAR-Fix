Charlie's session lessons (2026-05-20):

1. Don't treat one estimator as truth when it has a known datum offset.  Today's central mistake: PR #47's CSV reported Δ3D engine-vs-PRIDE; I read 1.64m and called it engine bias.  In reality, PRIDE-float (no phase biases) has a documented ~1.6-2m datum offset; engine was at UFO1 truth to 4mm.  Main caught it; I'd already cross-linked the wrong finding across three beads + a memory + a general broadcast.  Retraction was clean but the half-hour of cross-linking was wasted.  Lesson: when both sides of a comparison have known systematic offsets, validate against a THIRD reference (OPUS truth) before publishing the delta as a finding.  positionBiasFilterSideEvidence-charlie's 15.9cm-cross-host result still holds — it's an upper bound on receiver-side disagreement, NOT a truth measurement.

2. Forward-only mirror hooks bite quietly.  gt's bare → GitHub post-receive is one-direction.  GitHub-side merges via 'gh pr merge' don't propagate back.  Symptom: lab host pulls 'unrecognized arguments: --no-antposest' three hours after the merge.  Main reconciled with reset+force-push + sync all four lab hosts.  Now documented in CLAUDE.md (commit 934f986).  The general lesson: after any cross-system merge, verify both sides are at the same SHA before pushing more code.

3. Pre-commit hook will reject lab coordinates EVEN IN TEST DATA.  Today: 41.<lat> / -88.<lon> / 201.<alt> are all in the hook's secret-pattern list.  Three commits got blocked, requiring placeholder coords (40°N, 90°W) or LAT/LON/ALT tokens.  Lesson: when writing fixtures, default to placeholder coords; reach for real lab coords only when the test depends on them, and prefer constructed-via-lla_to_ecef over literal-embedded.

4. The 'works in batch but not incrementally' question often resolves to 'the receiver tracks signals the batch product doesn't cover.'  Today's PRIDE-batch-vs-engine gap on F9T-L5 captures = WUM publishes L1+L2 phase biases, our F9T fleet runs L1+L5, AR can't converge.  Sub-cm reproduction requires an L5-covering bias source.  This isn't a PRIDE bug; it's a coverage gap.  Documented in wumOsbBiaDownload-charlie close.

5. Repeated 'reach for memory + bead + general' pattern works for visibility.  When a finding has implications for multiple beads, a single discuss on the bead you OWN is invisible to the consumers who are reading OTHER beads.  Cross-link via discuss + use the General discussion section for top-level signal.  Validated when Main's dispute landed on positionBiasFilterSideEvidence-charlie within hours despite the finding originating in prideEpochDiff-charlie.
